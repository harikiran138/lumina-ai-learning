## What is Lumina?

Lumina is a full-stack, production-grade LMS designed specifically for the needs of Indian engineering institutions. It replaces generic one-size-fits-all platforms with a system that understands the unique structure of Indian higher education: multiple stakeholders (students, faculty, HODs, counselors, parents, mentors, alumni), semester-based curricula, and the need for institutional data sovereignty through self-hosting.

At its core, Lumina provides each student with an adaptive AI tutor that learns from their performance, identifies knowledge gaps, and generates personalized learning pathways. The platform uses state-of-the-art ML models — Bayesian Knowledge Tracing, Deep Knowledge Tracing, and spaced repetition via FSRS v5 — to continuously model each learner's mastery and surface the right content at the right time.

Lumina supports twelve distinct user roles, each with a dedicated portal. Faculty manage courses, verify AI-generated answers, and access granular analytics. Heads of Department oversee curriculum and faculty performance. Counselors receive early alerts from a dropout prediction model powered by XGBoost and SHAP. Parents track their child's progress. Alumni, peer tutors, and mentors participate in a connected institutional community — all within a single cohesive platform.

## The Teacher-Verified AI Queue

**This is the defining architectural feature of Lumina.**

No AI-generated answer ever reaches a student without explicit teacher approval. When a student asks the AI tutor a question, the response is generated by the LLM pipeline and placed in the `ai_answer_queue` table with `status = 'pending'`. It sits there until a faculty member reviews it in the Verification Queue portal.

Faculty can take one of four actions:

- **Approve** — the answer is released to the student as-is.
- **Edit and Approve** — the faculty member corrects or augments the answer before releasing it.
- **Reject** — the answer is discarded and the student is notified.
- **Escalate** — the question is flagged for a senior faculty member or HOD.

This design ensures that AI acts as a teaching assistant under human supervision, not as an autonomous oracle. The constraint is enforced at the database level via the `ai_answer_queue.status` column and Supabase Row Level Security policies — not merely in application logic.

## Key Features

**Adaptive Learning**
- AI Tutor with multi-turn conversation history per student per course
- Bayesian Knowledge Tracing (BKT) and Deep Knowledge Tracing (LSTM-based DKT) for real-time mastery estimation
- Adaptive learning pathway engine that reorders content based on learner state
- Flashcard system with FSRS v5 spaced repetition scheduling

**Teacher Control**
- Teacher-Verified AI Queue (approve / edit-approve / reject / escalate)
- Faculty-authored course content with lesson, unit, and module structure
- Manual and AI-assisted grading workflows for assignments and assessments

**Institutional Intelligence**
- XGBoost + SHAP dropout risk prediction with per-feature explanations
- Counselor portal with at-risk student dashboard and intervention tracking
- HOD portal with department-level analytics and curriculum approval workflows
- Attendance tracking and reporting across all courses

**AI and RAG Pipeline**
- OpenRouter LLM routing: Claude Haiku for simple queries, Claude Sonnet for complex reasoning
- Gemini API as a fallback provider; Ollama for local/offline development
- Hybrid RAG: FAISS dense retrieval + BM25 sparse retrieval + Neo4j knowledge graph, fused via Reciprocal Rank Fusion (RRF)
- TrOCR for handwritten assignment OCR and digitized evaluation

**Community and Gamification**
- Community forum with threaded discussions per course
- Gamification events, points, and achievement tracking
- Peer tutoring and alumni mentoring integrations
- Real-time notifications

**Multi-Portal Architecture**
- Twelve purpose-built portals covering every institutional stakeholder
- Role-based access enforced at API (`FastAPI Depends()` guards) and database (Supabase RLS) layers
- Institution-scoped data: all queries filtered by `institution_id`

## Quick Start

### Prerequisites

- Node.js 18+
- Python 3.11+
- A Supabase project (PostgreSQL database with RLS enabled)
- OpenRouter API key (sign up at openrouter.ai)
- Docker and Docker Compose (for containerized local development)

### 1. Clone the Repository

```bash
git clone https://github.com/your-org/lumina-ai-learning.git
cd lumina-ai-learning
```

### 2. Configure Backend Environment

```bash
cp backend/.env.example backend/.env
# Edit backend/.env — see Environment Variables section below
```

### 3. Configure Frontend Environment

```bash
cp frontend/web/.env.local.example frontend/web/.env.local
# Edit frontend/web/.env.local — see Environment Variables section below
```

### 4. Run the Platform

**Option A — One-command script (recommended for local dev):**

```bash
./run_local.sh
```

**Option B — Manual startup:**

```bash
# Terminal 1: Backend
cd backend
source .venv/bin/activate
uvicorn app.main:app --reload --port 8000

# Terminal 2: Frontend
cd frontend/web
npm run dev
```

**Option C — Docker Compose:**

```bash
docker-compose up --build
```

### 5. Access the Platform

| Service | URL |
|---|---|
| Frontend | http://localhost:3000 |
| Backend API | http://localhost:8000 |
| API Documentation (Swagger) | http://localhost:8000/docs |
| API Documentation (ReDoc) | http://localhost:8000/redoc |

### Backend (`backend/.env`)

| Variable | Required | Description |
|---|---|---|

| `JWT_SECRET` | Yes | Long random string used to sign JWT tokens |
| `REDIS_URL` | No | Redis connection URL for caching and task queues (default: `redis://localhost:6379/0`) |

## Key AI and ML Systems

### OpenRouter LLM Tiering

Lumina routes LLM calls by query complexity through OpenRouter:
- **Simple queries** (factual, short-answer): Claude Haiku for low latency and cost.
- **Complex queries** (multi-step reasoning, code, long-form explanation): Claude Sonnet.
- **Fallback**: Gemini API when OpenRouter is unavailable.
- **Local development**: Ollama with a locally running model (set `NEXT_PUBLIC_TUTOR_PROVIDER=ollama`).

### RAG Pipeline (Hybrid Retrieval)

Lumina uses a three-stage hybrid retrieval pipeline over course content:

1. **FAISS** — Dense vector similarity search over course content embeddings.
2. **BM25** — Sparse keyword retrieval for exact-term matching.
3. **Neo4j Knowledge Graph** — Graph traversal over concept and prerequisite relationships.

Results from all three stages are fused using **Reciprocal Rank Fusion (RRF)** before being passed to the LLM as context.

### Bayesian Knowledge Tracing (BKT)

A classical probabilistic model that estimates per-student per-skill mastery probability from assessment response sequences. Updates in real time as students complete questions.

### Deep Knowledge Tracing (DKT)

An LSTM-based neural model that captures long-range dependencies in student interaction sequences for more accurate mastery prediction than BKT alone.

### XGBoost Dropout Prediction with SHAP

An XGBoost classifier trained on engagement signals (attendance rate, submission latency, quiz scores, forum activity) predicts dropout risk per student. SHAP values provide per-feature explanations so counselors can understand exactly which factors are driving each student's risk score.

### FSRS v5 (Free Spaced Repetition Scheduler)

The state-of-the-art open-source spaced repetition algorithm (version 5) schedules flashcard reviews to maximize long-term retention while minimizing total review time.

### TrOCR

Microsoft's TrOCR model performs handwriting recognition on student-submitted handwritten assignments, enabling automated digitization and evaluation of handwritten work.

## Deployment

### Local Development

```bash
./run_local.sh
# or
docker-compose up --build
```

### Frontend — Vercel

The Next.js frontend deploys to Vercel. The `vercel.json` at the project root configures the deployment. Set all `NEXT_PUBLIC_*` environment variables in the Vercel project dashboard.

```bash
vercel --prod
```

### Backend — Railway or Self-Hosted

The FastAPI backend can be deployed to Railway using `backend/railway.toml`, or to any Linux server using Docker:

```bash
docker build -t lumina-backend ./backend
docker run -p 8000:8000 --env-file backend/.env lumina-backend
```

For a full production stack with Nginx and Redis:

```bash
docker-compose -f docker-compose.prod.yml up -d
```
