How Teachers create, organise, and manage courses, modules, lessons, and community boards.

---

## Course Structure Hierarchy

```
Course
└── Module (Chapter/Unit)
    └── Lesson (Lecture/Reading)
        ├── Content (PDF or video in MinIO)
        ├── Knowledge Components (mapped to BKT+DKT)
        └── Flashcards (auto-generated or manual)
```

## Course Fields

| Field | Type | Required | Description |
|---|---|---|---|
| `id` | UUID | Auto | Primary key |
| `institution_id` | UUID | Yes | Institution scope (enforced in every query) |
| `teacher_id` | UUID | Yes | Owning teacher |
| `name` | string (max 200) | Yes | Course title (e.g., "Engineering Mathematics II") |
| `description` | text | No | Course description shown to students |
| `branch` | string | Yes | Target branch (CSE, ECE, etc.) |
| `year` | integer (1–4) | Yes | Target academic year |
| `semester` | integer (1–2) | Yes | Semester |
| `department_id` | UUID | Yes | Department the course belongs to |
| `status` | enum | Yes | `draft`, `published`, `archived` |
| `created_at` | timestamptz | Auto | — |
| `updated_at` | timestamptz | Auto | — |

## Module Fields

| Field | Type | Required | Description |
|---|---|---|---|
| `id` | UUID | Auto | Primary key |
| `course_id` | UUID | Yes | Parent course |
| `institution_id` | UUID | Yes | Scope |
| `name` | string (max 200) | Yes | Module title |
| `order_index` | integer | Yes | Display order (0-based) |

## Lesson Fields

| Field | Type | Required | Description |
|---|---|---|---|
| `id` | UUID | Auto | Primary key |
| `module_id` | UUID | Yes | Parent module |
| `course_id` | UUID | Yes | Parent course (denormalised for query convenience) |
| `institution_id` | UUID | Yes | Scope |
| `name` | string (max 200) | Yes | Lesson title |
| `content_type` | enum | Yes | `pdf`, `video`, `text` |
| `content_key` | string | No | MinIO object key (set after upload) |
| `duration_minutes` | integer | No | Estimated reading/viewing time |
| `order_index` | integer | Yes | Display order within module |
| `kc_ids` | UUID[] | No | Knowledge Components this lesson covers |

## Community Board

Each course automatically has a community board. Every enrolled student can post and reply. Posts are moderated by the Teacher.

Post types:
- **Question** — student asks a question (not routed through AI queue — this is peer discussion)
- **Discussion** — open-ended topic for peer conversation
- **Resource** — student shares a link or file

Anonymous posting: Students can mark a post as anonymous. Their identity is visible to the Teacher and Faculty but hidden from other students. This is important for students who are afraid to show they don't understand something.

Peer Tutor can pin their own posts within the peer channel. Teacher can pin any post, hide any post, and delete any post.

## Flashcard Management

Teachers create flashcards per Knowledge Component. Flashcards are the FSRS v5 review units.

```
POST /api/courses/{course_id}/kcs/{kc_id}/flashcards
Body: { front: "string", back: "string", hint: "string|null" }
```

Flashcards can also be auto-generated by the Assessment Agent from lesson content (Teacher reviews before activating).

## Course Archiving

When a semester ends, Teacher or HOD archives the course:
```
PATCH /api/courses/{course_id} { status: "archived" }
```
Archived courses are read-only. Students retain their progress records and grade history. New enrollments are not permitted. Content remains in MinIO and FAISS index.
